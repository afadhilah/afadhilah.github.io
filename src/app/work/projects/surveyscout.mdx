## Overview

**SurveyScout** is a mobile marketplace application for field surveys built using Flutter. The platform connects three main actors: **Client** who need field data, **Surveyor** who collect data, and **Respondent** who fill out online surveys — all within one integrated ecosystem.

This project was developed as part of the Software Engineering course at ITS Semester 7, with focus on scalable mobile architecture, role-based access control, and modern UI/UX design.

void main() async {
  WidgetsFlutterBinding.ensureInitialized();

      code: `// router.dart — Role-based redirect
redirect: (context, state) {
  final authProvider = context.read<AuthProvider>();
  final isPublicRoute = publicRoutes.contains(state.matchedLocation);

  if (!authProvider.isAuthenticated && !isPublicRoute) {
    return '/login';
  }

  if (authProvider.isAuthenticated) {
    final role = authProvider.user?.role;
    if (role == 'client') return '/client/dashboard';
    if (role == 'surveyor') return '/surveyor/dashboard';
    if (role == 'respondent') return '/respondent/dashboard';
  }
  return null;
},`,
      language: "dart",
      label: "router.dart"
    },
    {
      code: `// database_helper.dart — SHA-256 auth
Future<Map<String, dynamic>?> loginUser(
  String email, String password
) async {
  final db = await database;
  final hashedPassword = _hashPassword(password);

  final result = await db.query(
    'users',
    where: 'email = ? AND password = ?',
    whereArgs: [email, hashedPassword],
  );

  if (result.isNotEmpty) {
    final token = _generateToken(email);
    final expiresAt = DateTime.now().add(Duration(days: 30));
    await db.insert('sessions', {
      'user_id': result.first['id'],
      'token': token,
      'expires_at': expiresAt.toIso8601String(),
    });
    return result.first;
  }
  return null;
}

String _hashPassword(String password) {
  final bytes = utf8.encode(password);
  return sha256.convert(bytes).toString();
}`,

## Database Schema

Uses local SQLite with two main tables and indexing for query performance:

<CodeBlock
  marginBottom="16"
  codes={[
    {
      code: `-- users table
CREATE TABLE users (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  email      TEXT    UNIQUE NOT NULL,
  password   TEXT    NOT NULL,  -- SHA-256 hashed
  name       TEXT    NOT NULL,
  role       TEXT    NOT NULL,  -- client | surveyor | respondent | admin
  phone      TEXT,
  avatar_url TEXT,
  created_at TEXT    NOT NULL,  -- ISO 8601
  updated_at TEXT    NOT NULL
);

-- sessions table
CREATE TABLE sessions (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id    INTEGER NOT NULL REFERENCES users(id),
  token      TEXT    NOT NULL,  -- SHA-256 generated
  created_at TEXT    NOT NULL,
  expires_at TEXT    NOT NULL   -- 30 days TTL
);

-- Indexes for query performance
CREATE INDEX idx_users_email    ON users(email);
CREATE INDEX idx_sessions_token ON sessions(token);`,

## Challenges & Solutions

<Grid columns="1" gap="16" marginBottom="16">
  <Card padding="24" radius="l" border="neutral-alpha-weak" direction="column" gap="12">
    <Text variant="heading-strong-s">Role-Based Navigation Complexity</Text>
    <Text variant="body-default-s" onBackground="neutral-weak">
      <strong>Challenge:</strong> 4 different roles with 80+ routes that must be organized structurally and securely.
    </Text>
    <Text variant="body-default-s" onBackground="neutral-medium">
      <strong>Solution:</strong> GoRouter ShellRoute per role with independent floating bottom navigation. Centralized auth guard in single redirect callback that checks AuthProvider state, so there's no security logic duplication.
    </Text>
  </Card>

    <Text variant="heading-strong-s">Consistent UI Across 72 Screens</Text>
    <Text variant="body-default-s" onBackground="neutral-weak">
      <strong>Challenge:</strong> Maintaining visual consistency across 72 Dart screens developed iteratively.
    </Text>
    <Text variant="body-default-s" onBackground="neutral-medium">
      <strong>Solution:</strong> Centralized design tokens in <InlineCode>app_theme.dart</InlineCode> and reusable widget library (<InlineCode>modern_widgets.dart</InlineCode>, <InlineCode>shared_widgets.dart</InlineCode>). Each screen uses the same components so theme changes apply globally.
    </Text>
  </Card>
  <Card padding="24" radius="l" border="neutral-alpha-weak" direction="column" gap="12">
    <Text variant="heading-strong-s">Realistic Mock API</Text>

      <strong>Challenge:</strong> Demonstrating full features without real backend requires convincing mock data.

## Outcomes & Learning

This project provides practical experience building **full-stack mobile application** with real-world complexity:

- Designing **role-based access control** that is secure using declarative routing
- Implementing **local-first architecture** with SQLite and state synchronization via Provider
- Building **consistent design system** for team developing many screens in parallel
- Understanding trade-offs between **mock API** for development velocity vs live backend for production readiness
- Managing **complex state** (auth, navigation, data) in a single multi-role application

SurveyScout proves that Flutter is capable of handling medium-to-large scale applications with clean architecture, good performance, and solid developer experience.
