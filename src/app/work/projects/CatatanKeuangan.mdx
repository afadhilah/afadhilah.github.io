## About Artharum

**Artharum** is a native Android application designed to help you record and manage personal finances easily. This application provides comprehensive tools for transaction tracking, managing multiple accounts, setting budgets, and analyzing expenses with intuitive data visualization.

### Application Purpose

Artharum was created to meet the following needs:
- **Record transactions** - Income, expense, and transfers between accounts
- **Manage multiple accounts** - Cash, bank, e-wallet, credit cards
- **Budget monitoring** - Set limits per category and track progress
- **Expense analysis** - Visualize distribution and financial trends
- **Make financial decisions** - Data-driven insights for financial planning

## Architecture

Artharum is built using **Clean Architecture** combined with **MVVM (Model-View-ViewModel)** pattern.

### Layer Architecture

```
┌──────────────────────────────────────────────┐
│         Presentation Layer (UI)              │
│    (Composable, ViewModel, Screen)           │
└──────────────────────────────────────────────┘
                    ↓ ↑
┌──────────────────────────────────────────────┐
│     Domain Layer (Business Logic)            │
│  (UseCase, Repository Interface, Entity)    │
└──────────────────────────────────────────────┘
                    ↓ ↑
┌──────────────────────────────────────────────┐
│     Data Layer (Database & Repository)      │
│  (Room DAO, Entity DB, Repository Impl)     │
└──────────────────────────────────────────────┘
```

### 1. Presentation Layer

Responsible for displaying UI and handling user interaction.

**Components:**
- **Composable** - UI components using Jetpack Compose
- **ViewModel** - Manages state and business logic for UI
- **Screen/Page** - Container for navigation
- **Event** - User interaction event

**Technology:**
- Jetpack Compose
- StateFlow for state management
- Navigation Component

**Structure:**
```
ui/
├── screen/
│   ├── dashboard/
│   ├── transaction/
│   ├── account/
│   └── budget/
├── component/
│   ├── Card components
│   ├── Charts
│   └── Custom UI elements
├── viewmodel/
│   └── ViewModel for each screen
└── navigation/
    └── Navigation graph
```

### 2. Domain Layer

Layer containing business logic and independent from framework.

**Components:**
- **UseCase** - Encapsulate business logic, one use case = one business function
- **Entity** - Domain model (representation of business data)
- **Repository Interface** - Contract for data access

**Example UseCase:**
- `GetAllTransactionsUseCase` - Retrieve all transactions
- `CreateTransactionUseCase` - Create new transaction
- `GetBudgetUseCase` - Get budget setting
- `CalculateNetBalanceUseCase` - Calculate net balance

**Structure:**
```
domain/
├── usecase/
│   ├── transaction/
│   ├── budget/
│   ├── account/
│   └── statistics/
├── entity/
│   ├── Transaction
│   ├── Account
│   ├── Budget
│   └── Category
└── repository/
    ├── TransactionRepository interface
    ├── AccountRepository interface
    └── BudgetRepository interface
```

### 3. Data Layer

Layer that handles storage and retrieval of data.

**Components:**
- **Room Database** - Local database for offline storage
- **DAO (Data Access Object)** - Database queries
- **Entity (DB)** - Database models
- **Repository Implementation** - Implementation of interface from domain layer
- **Mapper** - Convert between DB entity and domain entity

**Technology:**
- Room (SQLite)
- KSP (Kotlin Symbol Processing) for code generation

**Structure:**
```
data/
├── local/
│   ├── dao/
│   │   ├── TransactionDao
│   │   ├── AccountDao
│   │   └── BudgetDao
│   ├── entity/
│   │   ├── TransactionEntity (DB)
│   │   ├── AccountEntity (DB)
│   │   └── BudgetEntity (DB)
│   └── AppDatabase.kt
├── repository/
│   ├── TransactionRepositoryImpl
│   ├── AccountRepositoryImpl
│   └── BudgetRepositoryImpl
└── mapper/
    ├── TransactionMapper
    ├── AccountMapper
    └── BudgetMapper
```

## How to Run

### Prerequisites

<Row gap="12" marginBottom="16" wrap>
  <Feedback variant="info" marginBottom="0">
    <Text variant="body-default-m">
      <strong>JDK 21:</strong> Make sure to use JDK 21 (not Java 25)
    </Text>
  </Feedback>
</Row>

- **JDK 21** - Java Development Kit version 21
- **Android SDK 36.0.0** or higher
- **Android Emulator** or **Physical Device** with Android 12+ (API 31+)

### Quick Start

#### Run on Physical Device

```powershell
.\run-device.ps1
```

This script will:
1. Build debug APK
2. Install to physical device
3. Launch application automatically

#### Run on Emulator

```powershell
.\run-android.ps1
```

This script will:
1. Build debug APK
2. Install to running emulator
3. Launch application automatically

#### Build Only

```powershell
.\gradlew.bat :app:assembleDebug
```

Only build APK without installing and launching.

### Compile Check

To check if code compiles without errors:

```powershell
.\gradlew.bat :app:compileDebugKotlin
```

## Data Flow

Here is the flow of data from User Input to Display:

```
User Action (Click, Input)
           ↓
   ViewModel (Handle Event)
           ↓
   UseCase (Execute Business Logic)
           ↓
   Repository Interface
           ↓
   Repository Implementation
           ↓
   Room DAO (Database Query)
           ↓
   Database (SQLite via Room)
           ↓
   Response (Data back up through layers)
           ↓
   ViewModel (Update State)
           ↓
   Composable (Recompose & Display)
           ↓
   User Sees Updated UI
```
